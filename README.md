# TimeWise AI – System Prototype (Flutter / Dart)

ต้นแบบระบบ **A Decision Support System for Daily Time Allocation Using Artificial Intelligence**
(ระบบสนับสนุนการตัดสินใจในการจัดสรรเวลาสำหรับชีวิตประจำวันด้วยปัญญาประดิษฐ์)
รายงานวิชา 254374 การวิเคราะห์และออกแบบระบบ ภาคเรียนที่ 1 ปีการศึกษา 2569

## วิธีรันใน VS Code

### 1. สิ่งที่ต้องติดตั้ง (ครั้งแรกครั้งเดียว)
1. **Flutter SDK** เวอร์ชัน 3.22 ขึ้นไป → https://docs.flutter.dev/get-started/install
2. **VS Code** + ส่วนขยาย **Flutter** และ **Dart** (ค้นหาในแท็บ Extensions)
3. ตรวจสอบว่าพร้อมใช้งาน: เปิด Terminal แล้วพิมพ์
   ```bash
   flutter doctor
   ```

### 2. เปิดโปรเจกต์
1. แตกไฟล์ `timewise_ai.zip`
2. VS Code → **File › Open Folder…** → เลือกโฟลเดอร์ `timewise_ai`
3. เปิด Terminal ใน VS Code (**Terminal › New Terminal**) แล้วรันคำสั่งต่อไปนี้ **ครั้งแรกครั้งเดียว**

   ```bash
   flutter create . --project-name timewise_ai --org com.timewise
   flutter pub get
   ```

   > คำสั่ง `flutter create .` จะสร้างโฟลเดอร์ของแต่ละแพลตฟอร์ม (android, ios, web, windows, macos, linux)
   > ให้อัตโนมัติ และ **จะไม่เขียนทับ** โค้ดในโฟลเดอร์ `lib/` ที่มีอยู่แล้ว

### 3. รันแอป
- เลือกอุปกรณ์ที่มุมขวาล่างของ VS Code (Chrome, Android Emulator, Windows ฯลฯ) แล้วกด **F5**
- หรือใช้คำสั่ง
  ```bash
  flutter run -d chrome        # รันบนเว็บเบราว์เซอร์ (เร็วที่สุดสำหรับการสาธิต)
  flutter run                  # รันบนอุปกรณ์/Emulator ที่เชื่อมต่ออยู่
  ```
- ทดสอบอัตโนมัติ: `flutter test`

## ลำดับการสาธิต (สำหรับอัดวิดีโอ 4–5 นาที)
1. เข้าสู่ระบบ → หน้าหลักแสดงว่า “มีกิจกรรมมากกว่าเวลาที่ว่าง” (ต้องใช้ 9 ชม. แต่ว่าง 5 ชม.)
2. แท็บ **กิจกรรม** → เพิ่ม/แก้ไขกิจกรรม กำหนด Deadline และความสำคัญ
3. กดปุ่ม **ถาม AI** (ปุ่มกลางด้านล่าง) → ตรวจข้อมูล → **วิเคราะห์และสร้างทางเลือก**
4. เปรียบเทียบทางเลือก **A เน้น Deadline / B เน้นเป้าหมาย / C เน้นความสมดุล** พร้อมผลกระทบ 5 ด้าน
5. **ดูเหตุผล** → ปัจจัยที่ AI ใช้ตัดสินใจ → **ปรับแผน** (ลด/เพิ่มเวลา ย้ายช่วง เพิ่มงาน) ระบบคำนวณผลกระทบใหม่ทันที
6. **ยืนยันแผน** → ตารางเวลา → แตะกิจกรรมเพื่อ **บันทึกเวลาจริงและ Feedback**
7. แท็บ **รายงาน** → สรุปผล กราฟวางแผน vs ใช้จริง → ประวัติการวางแผน
8. ออกจากระบบ → เข้าด้วย `admin@timewise.app` → **ภาพรวม** → จัดการผู้ใช้ → สถานะระบบ (รีสตาร์ตบริการ AI) → บันทึกข้อผิดพลาด (ทำเครื่องหมายว่าแก้ไขแล้ว)
9. **ตั้งค่าระบบ** → เช่น เพิ่มน้ำหนัก Deadline เป็น 70% หรือเปิดโหมดปิดปรับปรุง → บันทึก → ออกจากระบบแล้วเข้าเป็นผู้ใช้ จะเห็นผลทันที

## ค่าที่ผู้ดูแลตั้งได้ และผลต่อแอปฝั่งผู้ใช้
| การตั้งค่า | ผลที่เห็นในแอป |
|---|---|
| น้ำหนักปัจจัย AI (Deadline / ความสำคัญ / เป้าหมาย / ประวัติ รวม 100%) | คะแนนรวมของทางเลือก A/B/C และทางเลือกที่ AI แนะนำ รวมถึงน้ำหนักในหน้าเหตุผล |
| เวลาสูงสุดต่องานในทางเลือก C | ทางเลือก “เน้นความสมดุล” จะไม่ให้งานใดยาวเกินค่านี้ |
| เวลารอ AI สูงสุด / แผนสำรอง | ข้อความในหน้า “AI กำลังวิเคราะห์” และเกณฑ์เตือนในกราฟสถานะระบบ |
| แจ้งเตือนก่อนเริ่มกิจกรรม | ตารางเวลาและหน้าการแจ้งเตือน |
| ความยาวรหัสผ่านขั้นต่ำ | การตรวจรหัสผ่านตอนเข้าสู่ระบบและสมัครสมาชิก |
| โหมดปิดปรับปรุงระบบ | หน้าเข้าสู่ระบบแสดงประกาศ และผู้ใช้ทั่วไปเข้าไม่ได้ (ผู้ดูแลยังเข้าได้) |
| ระยะเวลาเก็บประวัติ | บันทึกไว้เป็นนโยบาย (ในต้นแบบยังไม่ลบข้อมูลจริง) |

## หมายเหตุเกี่ยวกับ AI ในต้นแบบ
ไฟล์ `services/decision_engine.dart` ใช้ **กฎการให้คะแนนที่อธิบายได้ (rule-based scoring)** แทนการเรียก AI Service จริง
เพื่อให้ต้นแบบรันได้โดยไม่ต้องใช้อินเทอร์เน็ตหรือ API key

- **ทางเลือก A (เน้น Deadline):** เรียงตามวันครบกำหนด แล้วตามความสำคัญ
- **ทางเลือก B (เน้นเป้าหมาย):** เรียงตามลำดับเป้าหมายที่ผู้ใช้เลือก แล้วตามความสำคัญ
- **ทางเลือก C (เน้นความสมดุล):** ให้คะแนนรวม (ความสำคัญ + ความเร่งด่วน + เป้าหมาย) จำกัดเวลาต่องาน (ค่าเริ่มต้น 90 นาที ปรับได้ในหน้าตั้งค่าระบบ) และให้กิจกรรมสุขภาพได้เวลาก่อน
- **ผลกระทบ:** เวลาที่ใช้ งานที่เสร็จ งานที่ต้องเลื่อน ความเสี่ยงต่อ Deadline ความสอดคล้องกับเป้าหมาย
- **การเลือกคำแนะนำ:** คำนวณคะแนนรวม 0–100 จากปัจจัย 4 ด้าน ถ่วงด้วยน้ำหนักที่ผู้ดูแลตั้งไว้ (ค่าเริ่มต้น Deadline 40, ความสำคัญ 30, เป้าหมาย 20, ประวัติการใช้เวลา 10) แล้วเลือกทางเลือกที่ได้คะแนนสูงสุด

เมื่อพัฒนาระบบจริง สามารถแทนที่เมธอด `analyse()` ด้วยการเรียก Backend (Python/FastAPI) และ AI Service
โดยคืนค่าเป็น `AiResult` รูปแบบเดิม หน้าจออื่นไม่ต้องแก้ไข

## ใช้งานจริงบนโทรศัพท์
- ข้อมูลทั้งหมด **บันทึกลงเครื่องอัตโนมัติ** (`services/storage.dart` ใช้ shared_preferences) ปิดแอปแล้วเปิดใหม่ข้อมูลยังอยู่
- ครั้งแรกแอปจะมีข้อมูลตัวอย่างสำหรับสาธิต → **สมัครสมาชิก** หรือไปที่ **ข้อมูลส่วนตัว › เริ่มใช้งานจริง** เพื่อล้างข้อมูลตัวอย่างและเริ่มจากข้อมูลของตัวเอง
- ติ๊ก **จดจำฉันไว้** ตอนเข้าสู่ระบบ ครั้งต่อไปเปิดแอปจะเข้าหน้าหลักทันที
- ขึ้นวันใหม่ แผนของเมื่อวานจะถูกปิดและสรุปผลลงประวัติ กิจกรรมประจำวันกลับมาเป็น “ยังไม่เสร็จ”
- อยากอัดวิดีโอสาธิต: **ข้อมูลส่วนตัว › โหลดข้อมูลตัวอย่างสำหรับสาธิต**
- ข้อจำกัด: ข้อมูลอยู่ในเครื่องเดียว (ยังไม่มีเซิร์ฟเวอร์) การเข้าสู่ระบบไม่ได้ตรวจรหัสผ่านจริง และการแจ้งเตือนแสดงในแอปเท่านั้น ยังไม่เด้งเป็น push notification ของโทรศัพท์
- ในระบบจริงเต็มรูปแบบ ข้อมูลจะเก็บใน PostgreSQL ผ่าน Backend ตามที่ออกแบบไว้ในรายงาน
